Cortex doesn't have a memory problem.
It has an economics problem.

Ninety-four ideas across eleven lenses, run against the actual codebase — 10,552 lines, 4 schema versions, 5 locked eval suites. What came back wasn't "add more memory." It was that the most valuable thing Cortex can do is stop work from happening twice — and then prove it in tokens.

Lens 03 · TRIZ Contradiction

The tension the whole product sits on

Every agent-memory tool hits this wall. Cortex hits it harder than most because it's honest about budgets.

Memory only helps if it's in context

Unrecalled memory is worth zero. The instinct is always to inject more, earlier, more often.

VERSUS

Anything in context costs the work

Every token of memory is a token the actual task doesn't get. Better recall makes the working context worse.

TRIZ says: don't trade off — win both. You win both when a recall replaces an action instead of adding to it. "Here are three notes about auth" is a cost. "That file is unchanged since you read it at 14:02" is a refund — it deletes a 4,000-token re-read for 20 tokens. The second kind of memory is net-negative on context. Cortex currently ships almost none of it.

Convergence · Affinity clustering

Seven regions

94 candidates collapse into seven. Colour tracks Cortex's own decay model — hot is where the leverage is.

Region 01 · hot

The Context Economy

Cortex should be net-negative on tokens — and be able to prove it.
  • Read ledger. The session brief lists files already read and whether they've changed. Kills re-reads with zero interception.
  • Artifact cache. Content-addressed digests of files read; on re-read, answer "unchanged since 14:02" instead of resending 4k tokens.
  • Negative cache. Remember what wasn't there: "you grepped foo across src/ at HEAD abc — 0 hits." Failed searches are the most wasteful re-work.
  • Tool-output cache keyed on (command, HEAD, dirty set): "last npm test at abc was green and nothing you touched is in its path."
  • File cards. A 200-token distillation per hot file, regenerated on hash change — a replacement for the file, not a pointer to it.
  • Token P&L. token_ledger already exists. Turn it into injected-vs-saved and surface it in cortex stats.
Region 02 · warm

Current-Truth Depth

Memory that knows when it's wrong is already the moat. Go deeper into it.
  • Symbol-level validation. Wire LSP/Serena as the validator backend: a note about buildFullState goes stale when the function dies, not just the file.
  • Conflict detection. notes.conflict exists and is unused. "You decided X in June; you're now doing not-X."
  • Rejected alternatives as armor. notes.alternatives is barely surfaced. Showing "already rejected: X, Y" stops agents relitigating settled decisions.
  • Active revalidation on HEAD change, so staleness is known before retrieval, not computed during it.
  • Auto-supersede. Retroactive interference: a new decision on subject S demotes the old ones without a manual cortex_resolve.
Region 03 · hot

The Multi-Agent Hole

Today a 200k-token subagent run evaporates into one summary paragraph.
  • Auto-brief for subagents. cortex_brief currently requires the parent to paste. Give subagents an inherited read-only scoped session instead.
  • Write-back. Capture subagent conclusions as episodes automatically — the findings are the expensive part.
  • Claim bus. Parallel agents share an append-only scratch scope: "agent 3 already checked src/db — clean." Fan-outs stop duplicating each other.
Region 04 · emerging

Time-Shifted Memory

Memory that fires at the right moment instead of waiting to be searched.
  • Prospective memory is entirely missing. cortex_trigger(condition, message) — "when anyone next touches schema.ts, remind them migrations need a backfill."
  • Invariants → lint. A note asserting "we never import X in Y" compiles into a check. Decisions become enforceable.
  • PR contradiction checks. Post to CI: "this PR contradicts decision X."
  • Blame anchoring so "why does this line exist" resolves to the decision that produced it, and the anchor follows the code.
Region 05 · warm

Legibility & Operability

You can't trust or debug what you can't see — and right now you can't see any of it.
  • Basic CRUD is missing. No cortex ls, no show, no edit. A wrong note is permanent.
  • cortex doctor. Hooks are bash + jq. On Windows that's Git Bash, and when it breaks it breaks silently.
  • Storage hygiene. A 3.8 MB DB plus a 1.5 MB uncheckpointed WAL in the project root, colliding with worktrees. Move to ~/.cortex/<hash>/; add a checkpoint policy.
  • docs/decisions.md projection. Memory rendered as a git-tracked ADR file — diffable, reviewable, readable by any agent with no MCP at all.
  • Package split: cortex-core (zero-config, no hooks) + cortex-ambient. The install cliff is the adoption cliff.
Region 06 · cold

Reach & Substrate

One memory substrate across agents and repos.
  • User-global scope. "Node's /tmp isn't Git Bash's /tmp on Windows" isn't project knowledge — and today it lives in a different memory system entirely.
  • Absorb the neighbours. CLAUDE.md, AGENTS.md, and the Claude auto-memory MEMORY.md are three parallel memory systems with no shared substrate. That fragmentation is the pain.
  • Team memory via signed JSONL export/import, so decisions travel with the repo.
  • Multi-runtime. Codex, Cursor, Windsurf, Amp. Positioning: your memory, not your vendor's.
Region 07 · deep

Ranking Depth

Make ranking good enough that users never have to be sparing about what they save.
  • Ship the semantic layer. Plumbing exists and is gated off. A local ONNX model means no network, no key, no privacy cost.
  • Relevance feedback. Log whether a recalled item was actually referenced in the next edit — a real training signal.
  • Chunking. Notes always retrieved together should fuse, the way co-activated traces bind.
  • Two-stage retrieval: handles and one-line gists first, bodies only on request.

Synthesis

The connections you'd miss

Three hats, one idea

The artifact cache (lens 02), the negative cache (lens 02), and "memory that replaces work" (lens 03) look like three features. They're one move: make a recall cheaper than the action it prevents. That single sentence is the product.

Already built, never switched on

The two highest value-to-work items in the entire codebase are dormant columns. notes.conflict — contradiction detection. notes.alternatives — already-rejected surfacing. The schema anticipated both. Nothing reads them.

The hard part of the user's idea already shipped

ReferenceValidator, current_app_graphs, and file_renames were built to answer "is this memory still true?" The same machinery answers "is this file still as I read it?" — which is the artifact cache. It just points at notes instead of at content.

The 10-year view and the adoption bug are the same bug

Agents skip the tools because calling them costs more than not calling them. At 10M context, capacity stops being scarce and attention becomes scarce. Both say: Cortex wins on selection, not storage — and selection only gets called when it's cheaper than skipping it.

Killing the crown jewel produced a keeper

Delete the ranking engine and what survives is docs/decisions.md — memory as a git-tracked, human-reviewable, diffable document. Not a replacement for the DB: a projection of it. It makes memory auditable, and it works in any agent with no MCP at all.

The reframe
Today"Cortex remembers things across sessions."
→
The move"Cortex makes long agent sessions cheap — and shows you the receipt."

Memory-as-persistence is a crowded, unmeasurable claim: every tool says it, nobody can prove it, and the agent has no reason to call your tool over just re-reading the file. Memory-as-economics is measurable, demoable, and self-justifying — the more the agent uses it, the cheaper the session gets, and the number is right there.

Every recall should be able to answer: what did calling this save me?

This is also the honest fix for the adoption problem. One consult hint per session is a nudge. A tool that is cheaper than the alternative doesn't need nudging.
