- (technique by coach) started Assumption Reversal
- (insight by coach) Core assumptions to flip: memory=text notes; DB=per-project; notes=written explicitly; retrieval=agent-initiated; memory=read-only; one-agent-one-memory; memory serves the agent; scope=git branch; Cortex=passive.
- (idea by coach) FLIP memory-is-notes -> memory-is-CONTENT. Artifact cache: content-addressed digests of files read (hash+path+mtime+ranges); on re-read answer 'unchanged since 14:02' instead of resending the file.
- (idea by coach) Cheaper non-intercepting variant: cortex_seen(file) — 'have I read this, is it unchanged, here is my stored digest'.
- (idea by coach) Cheapest variant, zero interception: a READ LEDGER in the session brief — 'files already read this session and their state (unchanged / you edited it)'. Kills re-reads by making them visibly redundant.
- (idea by coach) Store DERIVED content not raw: a distilled 'file card' per hot file (exports, purpose, gotchas), regenerated only on hash change. A 200-token replacement for a 4000-token file.
- (idea by coach) Cache expensive TOOL OUTPUTS keyed by (command, HEAD oid, dirty-file set): 'last npm test at HEAD abc was green and nothing you touched since is in its path'.
- (idea by coach) Cache web/doc fetches (Context7, WebFetch) keyed by URL+day — agents re-fetch the same docs constantly.
- (idea by coach) NEGATIVE cache: remember what was NOT there. 'You already grepped foo across src/ at HEAD abc: 0 hits.' Failed searches are the most wasteful re-work.
- (idea by coach) FLIP per-project DB -> add a user-scope global memory layer (~/.cortex/global.db) for cross-repo insights like the Windows /tmp path gotcha. Merge project+user scopes, project wins ties.
- (idea by coach) Cross-project PATTERN memory: 'in your repos you always do X' — learned conventions, not just facts.
- (idea by coach) FLIP single-user -> team memory: signed JSONL export/import (cortex export --since / cortex import) so decisions travel with the repo.
- (idea by coach) FLIP explicit-write -> derived-write: an end-of-turn distillation pass writes the notes; cortex_note becomes the override, not the norm.
- (idea by coach) FLIP read-only history -> EXECUTABLE memory: store the repro command with the blocker so the next agent can rerun it, not re-derive it.
- (idea by coach) FLIP branch scope -> semantic scope: scope memory to subsystem/module, so 'the auth decisions' survive branch churn.
- (technique by coach) started TRIZ Contradiction
- (insight by coach) THE contradiction: memory only helps if it is in context, but anything in context costs the tokens the work needs. Every recall improvement makes the working context worse.
- (idea by coach) Win both with two-stage retrieval: recall returns HANDLES + one-line gists; the agent expands only the ones it wants. Pointers, not prose.
- (idea by coach) Win both by making memory REPLACE work instead of adding context: a recall that returns the cached test result or the file card is net-NEGATIVE tokens.
- (idea by coach) Make the P&L visible: the token_ledger table already exists — turn it into 'tokens injected by Cortex vs tokens saved'. This is the product's proof and its best demo.
- (idea by coach) Prefetch into the CACHE, not the context: warm the local store so tools are fast without injecting anything.
- (insight by coach) Contradiction 2: capture must be exhaustive to be useful but exhaustive capture is noise. Answer: explicit tiered storage — raw spool (7d) / episodes (90d) / notes (permanent), each queryable.
- (insight by coach) Contradiction 3: memory must be trusted but memory decays into lies. Answer: ACTIVE revalidation on HEAD change — a background pass so staleness is known before retrieval, not computed during it.
- (technique by coach) started Nature's Solutions (memory neuroscience)
- (idea by coach) Hippocampal replay / sleep consolidation: a real offline 'cortex consolidate' between sessions that rewrites episodic traces into semantic notes, instead of inline compression.
- (idea by coach) Schema conflict detection: the notes.conflict column exists and is UNUSED. Detect when a new note contradicts an old one and flag it — 'you decided X on Jun 6, you are now doing not-X'. Killer feature.
- (idea by coach) Chunking: notes that are always retrieved together should fuse into one chunk, the way human memory binds co-activated traces.
- (idea by coach) Testing effect, inverted: memory is currently strengthened by retrieval. Also WEAKEN memory that was retrieved and then ignored — the agent saw it and did not act on it.
- (idea by coach) Recognition beats recall in humans: offer a cheap recognition surface — a 5-line menu of memory SUBJECTS, expandable on demand — instead of forcing a search query.
- (idea by coach) Retroactive interference as a feature: a new decision on subject S automatically demotes older decisions on S. Auto-supersede rather than manual cortex_resolve.
- (idea by coach) PROSPECTIVE memory is entirely missing: cortex_trigger(condition, message) — 'when anyone next touches src/db/schema.ts, remind them migrations need a backfill'. Conditional, future-facing memory.
- (idea by coach) Priming: touching a topic should pre-activate related memory (raise hotness) cheaply, without injecting anything.
- (idea by coach) Working-memory capacity limit (7 plus/minus 2): hard-cap what is simultaneously 'active' and make that cap visible to the user.
- (technique by coach) started Ecosystem Thinking

- (idea by coach) Give subagents an auto-inherited read-only scoped session so they get a brief without the parent doing anything.
- (idea by coach) Capture subagent CONCLUSIONS back into parent memory — right now a 200k-token subagent run evaporates into one summary paragraph.
- (idea by coach) Cortex as a bus between PARALLEL agents: a shared scratch scope with append-only claims — 'agent 3 already checked src/db, clean' — so fan-outs stop duplicating work.
- (idea by coach) Wire Serena/LSP as the reference-validation backend to get symbol-level staleness for free.
- (idea by coach) Attach notes to git blame ranges so 'why does this line exist' resolves to the decision that produced it, and the anchor follows the code as it moves.
- (idea by coach) CI integration: post decisions as PR comments and flag 'this PR contradicts decision X'.
- (idea by coach) IDE gutter: hover a line, see the decision behind it.
- (idea by coach) Cortex should read/import the OTHER memory systems already on this machine — CLAUDE.md, AGENTS.md, the Claude auto-memory MEMORY.md. Three memory systems with no shared substrate is the actual user pain.
- (idea by coach) Nothing ever dies except derived data. Add 'cortex review' — a 2-minute triage of the oldest hot notes, human-in-the-loop.

- (idea by coach) Named/addressed memory: cortex_get('auth'). Deterministic, cheap, zero ranking risk. A hand-curated key-value layer may be 80 percent of the value.
- (idea by coach) Without retrieval, memory must be pushed at the right MOMENT — which makes trigger-based memory the entire product.

- (technique by coach) started Crank the Dial to 11
- (idea by coach) Dial trust to 11: full provenance chain per memory — which session, which commit, which command output produced it. 'Verified against HEAD abc 3 minutes ago.'
- (idea by coach) Dial latency to 11: a resident daemon over a named pipe / unix socket instead of a Node process per call. Sub-millisecond recall.
- (idea by coach) Dial scale to 11: 100k memories, 50 repos, 2 years. FTS plus linear rerank will not hold — needs an ANN index and sharding.
- (idea by coach) Dial automation to 11: Cortex writes ALL notes via an end-of-turn model pass; the agent never calls cortex_note.
- (idea by coach) Dial proactivity to 11: Cortex interrupts — 'stop, you are about to redo something that failed three times'.

- (technique by coach) started Failure Analysis
- (insight by coach) Real failure 1 — ADOPTION. The agent does not call the tools. One hint per session is a patch, not a fix. The fix is making recall genuinely cheaper than the alternative.
- (insight by coach) Real failure 2 — WINDOWS FRAGILITY. Hooks are bash plus jq; on Windows that is Git Bash. Fragile and silent when it breaks.
- (idea by coach) Replace the jq hook scripts with a tiny native/Node fast-path so capture cannot silently die.
- (insight by coach) Real failure 3 — the DB lives in the project root (3.8MB plus a 1.5MB uncheckpointed WAL). Needs gitignore discipline, collides with worktrees, and has no WAL checkpoint policy.
- (idea by coach) Move storage to ~/.cortex/<project-hash>/ with a project-root pointer; add a WAL checkpoint policy.
- (insight by coach) Real failure 4 — you cannot SEE what is in memory. No cortex ls, no cortex show, no edit. Debuggability is a product feature, and it is absent.
- (insight by coach) Real failure 5 — users are told to be sparing because notes compete for retrieval. That means memory is deliberately undersaturated. Better ranking should let you save everything.

- (idea by coach) Provocation 'the best memory is no memory' -> Cortex proposes code comments and ADRs from its notes, then forgets them. Memory that discharges itself into the codebase.

- (decision) CONVERGE: affinity clustering collapsed 94 candidates into 7 themes, then impact/effort scored them.
- (decision) CLUSTER 1 'Context Economy' — artifact cache, negative cache, tool-output cache, read ledger, file cards, two-stage handles, token P&L. Through-line: Cortex should be net-NEGATIVE on tokens and be able to prove it.
- (decision) CLUSTER 2 'Current-Truth Depth' — symbol-level validation, active revalidation on HEAD change, provenance, conflict detection, auto-supersede, rejected-alternatives. Through-line: memory that knows when it is wrong is the moat; go deeper into it.
- (decision) CLUSTER 3 'The Multi-Agent Hole' — subagent auto-brief, subagent conclusions written back, parallel-agent claim bus. Through-line: today a 200k-token subagent run evaporates; this is the biggest structural gap.
- (decision) CLUSTER 4 'Time-Shifted Memory' — cortex_trigger, invariants compiled to lint, PR contradiction checks, blame anchoring. Through-line: memory that fires at the right moment instead of waiting to be searched.
- (decision) CLUSTER 5 'Legibility and Operability' — cortex ls/show/edit/stats/doctor/review, decisions.md projection, DB relocation and WAL policy, package split, npx init. Through-line: you cannot trust or debug what you cannot see.
- (decision) CLUSTER 6 'Reach and Substrate' — user-global scope, cross-project patterns, team export/import, multi-runtime, importing CLAUDE.md and AGENTS.md and MEMORY.md. Through-line: one memory substrate across agents and repos.
- (decision) CLUSTER 7 'Ranking Depth' — local embeddings, relevance feedback, chunking, adaptive budgets, ANN scale. Through-line: make ranking good enough that users never have to be sparing with what they save.
- (decision) THE REFRAME: shift Cortex's identity from 'it remembers things' to 'it makes the session cheaper', with a measurable token P&L. This is the organizing idea — it justifies the cache work, gives the product a demo, and turns the core contradiction (memory costs the context it saves) into a scoreboard.
- (decision) TOP TIER, high impact and low effort: surface rejected alternatives in recall (alternatives column already exists, barely used); token P&L via the existing token_ledger plus cortex stats; the read ledger in the session brief; cortex ls/show/doctor.
- (decision) TOP TIER, high impact and medium effort: negative plus tool-output cache keyed on (command, HEAD, dirty set); conflict detection using the unused notes.conflict column; two-stage retrieval returning handles then bodies; subagent auto-brief and write-back.
- (decision) BIG BETS, high impact and high effort: the full artifact cache with PreToolUse short-circuit; cortex_trigger prospective memory; user-global scope merged into retrieval.
- (decision) PARKED: resident daemon, ANN/sharding, hosted team sync, IDE gutter — real, but premature before the P&L proves the value.
- (decision) CONSTRAINT TO RESPECT, not a feature: keep the injected memory block STABLE across a session so it does not invalidate the model's prompt cache; churn in injected context is a hidden tax.
- (insight) SYNTHESIS: three ideas from different techniques turn out to be one idea wearing three hats — the artifact cache (assumption reversal), the negative cache (also reversal), and 'memory that replaces work' (TRIZ). All three are the same move: make a recall cheaper than the action it prevents. That is the product.
- (insight) SYNTHESIS: the two most valuable features are already half-built and inert — notes.conflict (contradiction detection) and notes.alternatives (already-rejected surfacing). Both columns exist, neither is used. Highest ratio of value to work in the whole codebase.
- (insight) SYNTHESIS: reference validation was built to answer 'is this memory still true'. The same machinery answers 'is this FILE still as I read it' — which is the artifact cache. The hard part of the user's idea is already shipped; it just points at notes instead of at content.
- (insight) SYNTHESIS: the 10-year view (attention beats capacity) and the adoption failure (agents skip the tools) are the same problem. Both say the same thing — Cortex wins on SELECTION, not storage, and selection only gets called if it is cheaper than not calling it.
