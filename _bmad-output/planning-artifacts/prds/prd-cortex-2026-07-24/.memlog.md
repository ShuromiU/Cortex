- (decision) Intent: Create. Stakes: launch-grade (published npm package, public MCP/CLI surface). Working mode: Fast path — user said "keep going", so gaps are batched and inferences carry [ASSUMPTION] tags rather than being asked one at a time.
- (decision) Scope locked by user: 4-release roadmap PRD (R1 Context Economy, R2 Time-Shifted, R3 Substrate, R4 Depth) rather than the tighter 3-item build order or an R1-only doc. Reason: the release gates (R2 on SM-2, R3 on FR-24 stability, R4 on FR-41 data) are the roadmap's real content and are only visible when all four are written together.
- (decision) Data boundary locked by user: store content hashes + bounded model-derived summaries only; never raw file bytes. Rejected raw-with-redaction (makes redact.ts security-critical, grows DB toward repo scale) and hashes-only (forecloses substitution, which is where most savings live).
- (decision) Positioning reframe carried from brainstorm into the PRD's Vision: from "persistent memory" to "makes long agent sessions measurably cheaper". Rejected keeping persistence positioning (unprovable, crowded, gives the agent no reason to call the tool) and rejected fixing adoption with stronger consult hints (re-fights the settled pull-based redesign).
- (decision) Pulled FR-44 (retrieval-quality regression gate) forward from R4 into R1 MVP scope. Reason: it protects every other R1 change and costs little; Risk R-7 is that new memory kinds silently degrade retrieval.
- (decision) R1 internal ordering set by dependency, not size: Trust Activation -> Operability -> Read Ledger/P&L -> Content Cache -> Subagent Memory. Operability early so everything after it is debuggable; P&L before the cache so the cache is measurable on arrival.
- (decision) Deferred FR-40 local semantic ranking to R4 despite it being the most-requested-sounding item. Reason: the locked eval suites do not currently show lexical ranking as the bottleneck; building it earlier would be building on a hunch. Gated on FR-41 relevance data.
- (decision) Resident daemon deferred indefinitely and recorded in addendum, not the PRD backlog. Real latency win but introduces process lifecycle, crash recovery, stale-lock and version-skew failure modes the current architecture is free of.
- (decision) SM-C3 (false-confidence rate) defined as a zero-tolerance counter-metric — a single wrong "unchanged"/"no matches"/"tests pass" assertion is a release blocker. This is the constraint that shapes FR-6, FR-13 and FR-15: ambiguity must resolve to a miss, never to the convenient answer.
- (decision) Savings accounting restricted to identified avoided actions with recorded evidence. No modeled or speculative credit. Unrealized savings reported separately so the capability/adoption gap stays visible and SM-1 cannot flatter itself.
- (assumption) FR-17 subagent session linkage assumes the host harness exposes enough dispatch signal at the hook layer. Fallback defined (parent-initiated brief, opt-in write-back). MUST be resolved before the 4.4 epic is scheduled — the epic's size depends entirely on it.
- (assumption) FR-8 accounting assumes estimateTokens is accurate enough for the headline metric to be credible. If it drifts materially from real tokenization, SM-1 is fiction and the estimator must be replaced before R1 ships. Flagged to architecture in addendum A2.5.
- (change) Added Adapt-In clusters beyond the Essential Spine: Cross-Cutting NFRs, Public Surface and Compatibility, Performance Budgets, Constraints and Guardrails (Privacy/Safety/Cost/Data Governance), Risk and Mitigations, Why Now, Rollout, Dependencies. Justified by developer-product concerns (MCP/CLI are public contracts, schema migrations are durable) plus the new data boundary.
- (change) Dropped standalone Persona section per template guidance — persona context lives inline in UJ-1..UJ-4 with named protagonists.
- (event) Competitive grounding via web research: category (Mem0, Zep/Graphiti, Letta, LangMem) has consolidated on CONVERSATIONAL memory; none is repo-native, none validates against a working tree, none accounts for tokens. Token-cost problem independently validated — field mitigations (prompt caching ~90pct discount, server-side compaction) reduce the price of repetition, not the repetition. Recorded in addendum A3.
- (event) Reviewer gate run by the parent against the PRD quality rubric rather than dispatched to subagents — this session prohibits subagent dispatch unless the user requests it. Findings applied inline.
- (change) Reviewer gate applied: added Glossary terms (Load-bearing, Episode, App graph); completed Assumptions Index roundtrip from 1/7 to 7/7 inline tags; split Open Questions into 4 phase-blockers (Q1-Q4, architecture-owned) and 4 non-blocking with owners; promoted FR-30 predicate vocabulary to Q5 so a design decision cannot escape into implementation; stated UJ coverage as R1-scoped rather than inventing journeys for R2-R4.
- (event) PRD finalized — 44 FRs across 8 features and 4 releases, 4 UJs, 7 SMs + 4 counter-metrics, 9 NFRs, 6 compatibility rules, 8 performance budgets, 9 risks. status: final.
- (decision) Q1 RESOLVED YES: Claude Code hook payloads carry agent_id + agent_type; PreToolUse/PostToolUse fire for subagent tool calls; SubagentStart and SubagentStop both exist; SubagentStop delivers parent session_id + child agent_id + last_assistant_message; SubagentStart stdout is injected into the subagent context. Section 4.4 GROWS rather than shrinks — FR-18 needs no parent involvement, FR-19 gets a purpose-built payload.
- (decision) Q1 side-finding — LIVE DEFECT: subagent tool calls already fire PostToolUse today and are attributed to the PARENT session because session resolution keys on cwd. Empirically confirmed: 52 sessions in the working DB, all agent_type=primary, zero parent_session_id. Subagent activity has been silently polluting parent timelines. Scheduled as a bug fix AHEAD of the 4.4 feature work.
- (decision) Q2 RESOLVED — question dissolves: file cards need no model. Deterministic derivation (exported symbols from AST/LSP, purpose from leading doc comment, gotchas from notes referencing the file) covers the load-bearing content. Model enrichment becomes an opportunistic MCP path, never a dependency. Assumption retired rather than resolved; deterministic cards are also verifiable, which matters under SM-C3.
- (decision) Q3 RESOLVED — interception available; chose PostToolUse updatedToolOutput over PreToolUse deny. updatedToolOutput extended from MCP-only to all built-in tools in v2.1.121; this machine runs v2.1.170. Rationale: denial is a bet placed before the evidence exists; substitution is a claim made while holding the bytes. Cortex hashes what was just read and substitutes only on digest match, so it cannot assert falsely — SM-C3 satisfied by construction rather than by discipline. SM-2 ceiling no longer gated on the agent choosing to call a tool, and SM-2 becomes directly measurable.
- (change) Q3 forced two constraint amendments. Section 5 Non-Goals: 'Cortex does not block the user' carved out for verified Read substitution, fenced by 4 testable rules (digest match required, payload self-identifies, second read in a turn passes through, off by default and disableable). Section 10: B-4 split — non-substituting path stays 15ms, new B-4a allows 100ms for the Read substitution path because measured sha256sum on a 57KB payload costs ~54ms on Windows/Git-Bash. Digest lookup must stay Node-free via a flat greppable index so N-4 holds.
- (decision) Q4 RESOLVED — project identity = hash of absolute realpath of git rev-parse --git-common-dir, with root-commit OID stored as a repair anchor. Verified on this machine including a path containing a space. git-common-dir resolves all worktrees of a repo to one store (correct — Cortex partitions worktrees internally by scope key); separate clones get separate stores (also correct). Rejected: remote URL (breaks local-only repos, makes a fork share upstream memory), root-commit-as-primary (forks share a root commit, empty repos have none), committed id file (invasive). Risk R-4 repair: on cold start with no store, adopt a store whose root-commit OID matches and whose recorded path no longer exists.
- (event) All four architecture phase-blockers resolved by empirical investigation rather than design reasoning — Claude Code v2.1.170 hook reference, live Cortex database inspection, and git primitive testing on the target Windows configuration.
